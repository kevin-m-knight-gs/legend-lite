## Findings

1. **FIXED — a silent default.** `ContextReading.driverTablePkOf` read the option only as
   a literal `true`; any other spelling read as false without a word. The reader never
   guesses: a non-literal value is now loud (`NotImplementedException`).
2. **FIXED — a magic depth.** `StatementInline`'s thin-wrapper rule stopped at depth 4, a
   number inherited from the deleted call-frame route (`hasNonLetIntermediate`). The
   memo already scores an in-progress callee false, so a tail-call chain ends at a
   non-program or a cycle; the cap is gone.
3. **OWED — the option is program-wide.** `StatementExecutor.driverTablePkRequested`
   derives ONE environment flag from any execute call in the program; the engine's
   option is per execute call. This is parity with the thread-local it replaced (set
   once per resolve), not a regression, but the principled home is the execute
   envelope's own bound context (`TypedFrom.context().driverTablePk()`), applied by the
   resolver where it meets that from. Sized: DriverPkAppend's five env consumers move
   to the from's context.
4. **OWED — the same static-sink family.** `PostProcessBoundary` carries the connection
   post-processor state (table renames, CTE extraction, non-executable, time zone) in
   thread-locals set per execute and read by the text-verdict surfaces; `PctRenderOption`
   likewise. These are execution options exactly like the one batch 118 moved onto the
   program. Batch after item 5.
5. **NOTED — dead-until-needed code.** `CollectionLanes.registerFirstNotNull`'s
   variant-lane json-null nullification for COMPUTED elements is exercised by no corpus
   test (every demanded call is a literal collection). It reuses the platform's own
   spelling helper and follows the spec body; kept, named here so it is not mistaken for
   tested surface.
6. **NOTED — one interpretation left in the harness.** The vacuous-body check (a test
   whose body is the literal `true`) is Pure read by the harness; a `ProgramFacts.vacuous`
   fact would remove it. Trivial; folded into item 5's batch or the next.
7. **CLEAN.** `ResolvedNames.referents` is the one reading of the resolver's output;
   `ProgramFacts` reads seeds through the one context reader and verdicts through the
   catalog; the exeCtx execute overload is identified by its SIGNATURE, never by shape;
   the prelude gained `RelationalExecutionContext` by Java demand, from spec.
